



La ISO/IEC 27017:2015 es un estándar internacional que extiende los controles de seguridad de la información de ISO 27002 específicamente para servicios en la nube, aplicable tanto a proveedores (CSP) como clientes (CSC). Proporciona orientación detallada para 37 controles existentes y añade 7 nuevos controles cloud-específicos (CLD), enfatizando el modelo de responsabilidad compartida en entornos IaaS, PaaS y SaaS. [glocertinternational](https://www.glocertinternational.com/resources/guides/what-is-iso-27017/)

## Visión General y Alcance
La norma ISO/IEC 27017, titulada "Código de práctica para controles de seguridad de la información basados en ISO/IEC 27002 para servicios en la nube", fue publicada en 2015 y desarrollada por el comité ISO/IEC JTC 1/SC 27 para abordar riesgos únicos del cloud como multiinquilino, virtualización y responsabilidades compartidas. Su alcance cubre todos los tipos de organizaciones que proveen o usan servicios cloud (públicos, privados, híbridos), independientemente del tamaño o sector, y se integra al Sistema de Gestión de Seguridad de la Información (SGSI) de ISO 27001 mediante la inclusión en la Declaración de Aplicabilidad (SoA). No es certificable de forma independiente, sino como extensión de ISO 27001, con una revisión en curso para 2025 que actualiza referencias a ISO 27002:2022. [advisera](https://advisera.com/27001academy/blog/2015/11/30/iso-27001-vs-iso-27017-information-security-controls-for-cloud-services/)

## Relación con ISO 27001 y 27002
ISO 27017 se basa en la estructura de cláusulas 5-18 de ISO 27002, extendiendo 37 controles con guías específicas para cloud (separadas para CSP y CSC) y añadiendo 7 controles nuevos (CLD.6.3.1 a CLD.13.1.4) que abordan gaps como segregación virtual y remoción de activos. A diferencia de ISO 27001 (certificable, enfocada en SGSI), ISO 27017 es un código de práctica no auditable solo, pero sus controles se incorporan al Anexo A de ISO 27001 para auditorías integradas; por ejemplo, en acceso (cláusula 9), añade gestión de identidades multiinquilino y APIs. Con ISO 27018 (privacidad PII en cloud público, 25 controles nuevos), difiere en foco: 27017 es seguridad general cloud vs. 27018 ciclo de vida de datos personales. [kiteworks](https://www.kiteworks.com/es/glosario-riesgo-cumplimiento/iso-27000-estandares/)

## Controles Adicionales y Extensos
Los 7 controles CLD son: CLD.6.3.1 (roles compartidos: matriz de responsabilidades CSP/CSC/shared/NA); CLD.8.1.5 (remoción segura de activos cliente al fin de contrato, borrado de backups/replicas); CLD.9.5.1 (segregación virtual: aislamiento lógico de tenants via hypervisors, redes SDN); CLD.9.5.2 (endurecimiento VMs: imágenes baseline seguras, patching automatizado); CLD.12.1.5 (seguridad admins: monitoreo privilegiado, just-in-time access); CLD.12.4.5 (monitoreo servicios: logs accesibles a CSC para métricas/availability); CLD.13.1.4 (alineación redes virtual/físicas: políticas uniformes en firewalls/micro-segmentación). Extensiones incluyen operaciones (cláusula 12: change mgmt multi-tenant, capacity anti-DDoS); comunicaciones (13: API gateways, hybrid cloud networking); cripto (10: keys customer-managed). [ignyteplatform](https://www.ignyteplatform.com/blog/security/iso-27017-cloud-controls/)

## Modelo de Responsabilidad Compartida
Central en ISO 27017, define matrices por servicio (IaaS: CSP física/hypervisor, CSC OS/apps; PaaS: CSP + middleware; SaaS: CSP stack completo, CSC config/data), eliminando ambigüedades contractuales con niveles CSP/CSC/Shared/NA. Ejemplo to tabla: |Área|IaaS|PaaS|SaaS| -> Física: CSP; Datos: CSC/Shared. Requiere documentación explícita, revisiones periódicas y alineación SLA; CSP informa ubicaciones geográficas/datos para compliance legal. [ignyteplatform](https://www.ignyteplatform.com/blog/security/iso-27017-cloud-controls/)

## Implementación y Certificación
Proceso: 1) Gap analysis vs. controles; 2) Actualizar SoA ISO 27001 con CLD/extensos; 3) Implementar (e.g., hardening VMs via Ansible, monitoreo Prometheus); 4) Auditoría interna; 5) Certificación: Etapa 1 (docs/riesgos/SoA), Etapa 2 (eficacia/evidencia, 1-2 semanas). Timeline: 2-4 meses si ISO 27001 existente; beneficios incluyen resiliencia (backups encriptados), confianza (reducción brechas 30-50% típica) y ventaja competitiva.
